# 大往生与 Espgaluda 第一至五面

## 大往生 V101 原程序

`probe_ddpdoj.lua` 可用 ShmupMAME 5.4 的 `-autoboot_script` 在独立目录执行，导出解密后的 `ddpdoj-program.bin` 并记录最初的回调挂载。运行以下命令可导出五面共 2237 条生成指令和 36 个敌弹模板。

```powershell
python tools/pgm/inspect_ddpdoj.py ddpdoj-program.bin --spawns spawn.csv --bullets bullet.csv
```

原程序的 `0x161c4c` 按主卷轴计数消费 8 字节生成指令。开场的 `0x11` 小机从各自的路径入口初始化，`0x161eba` 写入逐帧回调 `0x167158`。该敌机调用 `0x17fc9a` 发射 `0x0d` 弹，弹体首帧回调 `0x18110a` 再登记 `0x181146`。探针已在运行时读回小机与弹体的两种挂载。整关练习仍使用下面记录的旧数据。

### 原生移植的复现和验证

从解密后的 V101 程序和本地 ROM 图形数据重新导出五面的生成表、两路卷轴指令、地图图块、路径和定点速度表。

```powershell
python tools/pgm/export_ddpdoj.py ddpdoj-program.bin E:/Downloads/shmupmame_5.4_win64/roms/ddpdoj.zip --output mod/GAME/th44/native --resources Resources/th44/native
luajit tools/pgm/check_ddpdoj.lua
```

原生试运行入口为 `mod/GAME/th44/native/runtime.lua`。一面开场回归覆盖小机、大机、两组坦克和 `0x85` 双判定盒机体。主卷轴计数 `0xbc` 时，`0x171314` 登记小机增援，下一帧按队列分配敌机槽并挂载父对象给出的路径与坐标。

`0x172228` 战舰交替推进主炮扇射和双炮塔齐射。回归对照两次扇射与首次炮塔齐射的角度、坐标及定点速度，并检查击破后 `0x172616` 登记的六个主爆炸和碎片对象。自机短按射击时，两种机体的机身弹从 `0x148e3a` 所用的 ROM 表取参数，经 `0x152ce8` 分派出膛、飞行和命中回调。受击测试覆盖扣减残机及补机装载。

长按射击时，`0x14b398` 先推进副机聚拢，`0x153e28` 由激光头动画指令登记命中框。回归对照两种机体和三种人形的副机首发、聚拢时序、激光起射帧及近处目标截短后续判定。伤害按 `0x15e916` 写入的单人或双人标志折减。普通炸弹走 `0x155048`，激光炸弹走 `0x1551ec`。两种炸弹的持续时间，以及激光炸弹撞上地物时的停束坐标、第一笔伤害和后坐均有受控对照。

Hyper 道具占用独立的空中道具槽。`0x17d816` 按 ROM 位移表推进道具，`0x15231a` 在碰撞后的处理帧增加库存并写入计时。`0x148b0c` 和 `0x183e80` 消费库存，机体弹、副机弹和激光切换到各自的 Hyper ROM 表。回归对照了道具前四帧的坐标、Type A 射击强化人形的首轮机身弹和副机弹，并测试了激光表切换、计时耗尽和候补道具出场。开场小机、大机和三面侦察机击破时已挂载 `0x1849fc` 的充能分支。道具回归以受控输入补满槽，其余计分事件的充能挂载尚待补齐。

`0x174362` 的补给机会在击破时申请空中 P 或炸弹补给。四面中 Boss 的 `0x179d46` 也走 `0x17d0d8`，把残机奖励登记在独立空中槽。回归对照 P 道具首四帧位置，检查拾取次帧提升射击与激光等级、满级道具转为 1000 分、补给炸弹及增加残机。坠毁时在自机位置登记补给，补机装载时按人形降级武器，并依 Hyper 状态决定是否提高炸弹上限。进入二周目时，`0x18e588` 把炸弹数量和上限一并恢复为人形的初始值。`0x1827ae` 在加分后检查默认的两次加命门槛。首面关底的 `0x192eca` 与 `0x192fae` 从击破的翼部位置掉落 Hyper，旋转阶段还从另一翼的位置分配一颗。

`0x169f86` 中 Boss 的舰身与八座炮台占用各自的原版部件槽。回归对照炮台转动与首发、舱门两轮发弹、单炮台受击及击破，以及主舰击破后的清弹掉落和卷轴恢复。`0x16aa82` 在下一次生成队列消费后，按原版硬件行替换背景残骸图块。

中 Boss 后的炮车 `0x17302e` 使用两侧固定炮管和独立炮塔。回归对照两类炮口的首发帧、角度和速度，并跑过后续坦克、地炮、飞机掠过和警告直到一面关底的生成记录。单人横向视野使用 `0x15fcfa` 的定点位移和画面边缘切换条件。

关底初始化 `0x1908e2` 调用 `0x15860a`，同时挂载本体阶段表 `0x19130c`、攻击表 `0x193ab6`、绘制表 `0x190b3a` 以及两组部件任务表 `0x19190a` 和 `0x1931d4`。攻击任务有 10 个执行槽，两组部件任务分别有 10 和 5 个，每槽记录初始化是否已执行。

原生回归从第一面道中运行到 `0x190b0a`，经过本体机动阶段，再通过原有伤害入口触发关底退场与通关标志。入场、首次四炮扫射和首次双翼发弹与 V101 坐标、发射帧、角度、速度一致。`0x192e9c` 和 `0x192f80` 的判定按左翼到右翼的顺序处理，先击破左翼时右翼当帧也进入拆解。

第二面由原生运行器读取生成表，可运行到卷轴 `0x1dc` 的关底生成记录前。`0x176268` 的双判定盒飞机按舱门计时开火，`0x1752b8` 浮炮与 `0x175e82` 地炮击破后保留底座。`0x173b18` 随路径放开判定盒并轮流打开两侧炮口，`0x17814a` 在高位恢复受击后的耐久并增加补给掉落，`0x178dfa` 根据炮门图像表改变侧边判定并在击破时进入清弹与残骸状态。

第二面中 Boss `0x1774c0` 的两块盒共用 `0xb000` 耐久，每帧以两块中较大的伤害扣血。回归逐颗对照主炮首轮、双翼首轮及散射首发的坐标、角度、速度和弹体回调。后续货舱 `0x1783e0`、`0x178624`、`0x1787fc` 在各自的击破计时耗尽后掉落。巡航机 `0x1767d8` 与舱门炮 `0x178a66` 的首发也有逐帧对照。测试按原版断点初始化 Rank、随机游标和自机坐标。

第二面关底 `0x1955ea` 分配 12 个部件槽，经 `0x15860a` 登记本体阶段、攻击和部件任务表。LuaSTG 回归从道中进入关底，逐颗对照 `0x198158` 首轮六发的坐标、角度、速度和弹体回调，再通过伤害入口推进炮台拆解、本体变形、`0x7700` 阈值、`0x18151e` 弹体放行和本体退场。最后一段从本体进入击破状态到通关标志经过 437 个更新帧。个别攻击分支、烟尘和屏幕演出仍有缺项。

第三面小机 `0x163d14` 和战舰 `0x16250a` 使用原版路径和炮口表。卷轴 `0x3b` 同帧生成侧舱门 `0x16526e` 和地炮 `0x163034`。回归核对侧舱门开度改变碰撞范围、地炮击破后保留底座，以及 `0x163710` 四座旋转炮的原版保护计时和首轮发弹。地炮和旋转炮使用 `0x141726` 对应的副卷轴位移。

第三面中 Boss `0x16ac58` 使用最近十个机身位置更新两翼判定。回归对照首轮双翼 14 发、舱门子机的生成位置和首发炮弹、左翼独立击破、本体耐久降到 `0x2800` 触发拆解，以及击破后恢复主卷轴。主卷轴恢复后，`0x16452c` 登记舰艇 `0x164710`、`0x164c6c`。测试逐颗核对 `0x1734f8` 飞船、`0x1656c0` 炮塔和 `0x164c6c` 舰艇的首轮发弹。

第三面关底 `0x19a11e` 依照任务表 `0x19a5d6`、`0x19b580`、`0x19a7e4` 和 `0x19aebe` 更新机身、翼炮及可拆部件。五处受击框共享耐久，本帧有多处受击时取最大伤害。回归核对机身狙和翼炮首轮，在 `0x11800` 阈值下验证变形保护及翼舱脱离，并验证本体击破后第 436 个更新帧出现通关标志。部分特殊难度分支、碎片与缩放演出尚未逐帧核对。

第四面开场脉冲 `0x177246` 由炮塔 `0x176d7a` 读取。回归对照 `0x17b918` 的舱门首轮和 `0x179792` 母舰舰炮，验证附属机起火、失去判定以及舰体开放受击的顺序。中 Boss `0x17a030` 的机身和两翼有独立耐久，舱门按程序帧推进并登记子机 `0x17aba2`。回归对照翼炮首发、首次开舱散射、第二轮扇射的部分炮弹及子机出舱位置，再通过受控伤害验证左右翼拆解和机身的 192 帧退场。

第四面后段炮塔 `0x17bf2e` 的副炮判定随横移更新，主炮开火期间锁定横移位置。回归对照八发侧炮和四发主炮的首发坐标、角度、速度及弹体回调。末段机库 `0x17b0c0` 由纵向位置推进舱门、升降台和碰撞，回归验证两个重合的机身判定框只扣一次最大伤害。

第四面关底 `0x19d21c` 分配 13 个部件槽。本体、移动、攻击与部件任务分开推进，两个耐久阈值 `0x23000`、`0xc400` 分别触发变形和翼部脱离。回归对照入场及两侧炮轮的首发，检查重合机身判定每帧取最大伤害、翼部伤害隔一帧折半并入本体，以及击破后第 439 个更新帧出现通关标志。后续攻击、旋转子机和爆炸演出还有分支待逐帧对照。

第五面开场旗舰 `0x1728de` 各自推进舰炮与舱门，回归逐颗对照首轮 14 发箭弹与四发舱门弹。卷轴 `0x9e` 的入场机 `0x16c69a` 按门帧排队生成首个中 Boss `0x16c892`。中 Boss 的三个判定框共用耐久，俯冲后的攻击任务登记有独立接触判定的喷焰对象 `0x16d4ba`。回归核对中 Boss 首轮 23 发环射和五发瞄准弹，并通过伤害入口验证机体与喷焰退场。

第五面后续的地炮 `0x16f69e` 逐帧开门并锁定一轮的三发炮弹，舱门 `0x16f94a` 登记浮台 `0x170c8c`。回归对照地炮首组三发及浮台 15 发首轮，并检查浮台升起时判定盒的变化和初期保护解除。

卷轴 `0x160` 的地堡 `0x16c038` 交替发射带角加速度的旋转环和镜像扫射。回归对照旋转环首轮八发，并按原版受控伤害断点核对退场帧。卷轴 `0x1b8` 的中 Boss `0x16de5a` 在飞行任务之外独立推进前后炮座，炮座排队登记滑行部件，部件再分裂成独立对象。回归核对第一次四种部件的坐标、速度及接触判定，以及投放的 `0x52` 子机被击破后的回收。后段轨道炮、重坦克和路口舰艇推进到卷轴 `0x31a`，由关卡生成表登记最终 Boss `0x1a2938`。

第五面关底分配 16 个部件槽。一周目使用 `0x1a7556` 攻击任务表，`0x1a4e7e` 先取八个判定框当帧的最大伤害，再执行任务。回归核对入场、耐久写入、首个攻击循环中四个任务的发弹，以及返回第一个任务后改变的箭弹速度。耐久低于 `0x2a000` 后，回归检查转段期间的防御、首轮八发 `0x181746` 敌弹的坐标与方向及单次反射。击破依次推进 `0x1a3d2e` 与 `0x1a4e64`，第 319 个更新帧回收机体并发出通关标志。

二周目末关的 `0x1a559e` 有 14 个攻击入口。原生运行器逐一调度，其中 `0x1a71f2` 会在首次等待前撤销自身。回归逐颗核对首轮箭弹、两类滑行弹和核心阶段的部分发弹，核对滑行弹的初始定点速度、回调挂载和起步条件。`0x1a4188` 另行登记本体变形。第一形态击破后保留两个舰体判定框，第二次变形后开放核心。回归验证炸弹触发核心横向碰撞框扩张、剩余耐久 `0x23000` 以下启用最后的防御任务，以及核心击破后第 308 个更新帧放出最后一批碎片、第 437 个更新帧发出通关标志。

`0x15f43a` 根据面序、累计时间、周目和 Hyper Rank 更新 `0x813002` 至 `0x813020`。回归逐项对照 V101 的三个检查点，换面时保留计时。Windows LuaSTG Sub 受控回归使用同一自机跑过两周目十面，关底通过原有时限分支推进。LuaJIT 另用持续射击和方向键跑完两周目，保持自机保护位开启，Boss 耐久和时限自然推进。实战充能、全面计分、关间演出和个别攻击分支仍需核对。硬件减速及部分缩放和爆炸演出仍有差异。游戏菜单的整关练习仍走旧版入口。

## 旧版整关练习

关卡练习入口为「怒首领蜂大往生 · 第一至五面」（TH44，level 42）与「Espgaluda · 第一至五面」（TH45，level 43）。两作从第一面连续推进。机体分别为 Type A 与 Ageha。射击键发通常弹，按住切换激光，射击加低速键可直接发激光，符卡键使用炸弹。

运行时使用 LuaSTG 对象。离线导出读取 68000 的敌机控制器、敌弹池、精灵表、背景图块和滚动寄存器。每颗弹保存实测的出生坐标、逐帧速度变更、贴图和判定状态，包含同一弹池槽位内从预备到运动的变化。能用横移对照确认的自机狙会重新瞄准。关底的原生判定对象按每帧原作部件位置和非对称判定盒更新。

## 关底行为来源

- 大往生第一面关底 `0x0e80` 的机身与两侧部件分别使用控制器 `+0x16`、`+0x1a`、`+0x1e`。在 `0x192d44`、`0x192e14`、`0x192ef8` 分别累计伤害，部件初始化为 `0x9000`，机身为 `0x16c00`。左右两边先击破的路径分别实测采样。机身击破后播放原采样爆炸，再进入第二面。
- Espgaluda 第一面关底 `0x6080` 由 `0x18deda` 处理多判定盒的伤害。初始总量为 `0x32600`，两段累计伤害为 `0x15200` 和 `0x1d400`。第二面关底 `0x6a80` 的原程序 `0x190ccc` 在剩余血量降至 `0x19300` 时换段。两处都采了后续攻击与击破演出。
- 大往生第三面关底 `0xa080` 在 `0x19ad2e` 比较剩余血量和 `0x11800`。Espgaluda 第三面关底 `0x6d80` 在 `0x1934ce` 与 `0x1935fc` 依次比较 `0x33cc0` 和 `0x168c0`。第三面击破后进入第四面。
- 大往生第四面关底 `0x4080` 在 `0x19e10e`、`0x19e148` 比较 `0x23000` 和 `0xc400`。Espgaluda 第四面关底 `0x7181` 由 `0x1993e4` 处理多个计数器。采样时手动触发计数器越线，LuaSTG 使用对应伤害量进入各段。
- 大往生第五面关底在 `0x1a5036` 比较 `0x2a000`，击破后从 `0x1a506c` 进入清场。Espgaluda 第五面关底的 `0x1bc5b4` 先扣前段计数 `0x41000`，`0x1bc908` 处理后一段击破。导出将这两个攻击段和击破演出接在对应伤害入口。
- Windows LuaSTG Sub 隔离测试通过原生伤害入口加速击破，检查左右部件、阶段切换、关卡衔接及返回菜单。

## 复现导出

在游戏目录使用 Python 3、NumPy、Pillow 和 ShmupMAME 5.4。模拟器的 ROM 目录中，大往生需要 `ddpdoj.zip` 及其父集 `ddp3.zip`。

先准备以下采样。运行 `tools/pgm/capture.lua` 时用 `PGM_GAME` 指定游戏、`PGM_TRACE` 指定输出路径。使用不同的工作目录隔离模拟器存档。 `PGM_MODE` 使用 `primary` 或 `shift`，`PGM_BOSS_ROUTE` 只用于下表标注的伤害采样。

| 传给导出器 | 大往生采样帧与路线 | Espgaluda 采样帧与路线 |
|---|---|---|
| `--primary` | 1300–12500，`primary` | 1300–12500，`primary` |
| `--shift` | 1300–12500，`shift` | 1300–12500，`shift` |
| `--damage` | 7700–22000，路线 `left` | 8100–22400，路线 `phase` |
| `--right-damage` | 7900–9600，路线 `right` | |
| `--third` | 20000–29400，路线 `campaign` | 20000–29400，路线 `campaign` |
| `--third-tail` | 29399–35500，路线 `campaign` | 29399–35500，路线 `campaign` |
| `--fourth` | 35199–49900，路线 `later` | 35199–50500，路线 `later` |
| `--fifth` | 49749–67500，路线 `final` | 49749–67500，路线 `final` |
| `--fifth-tail` | 67499–81000，路线 `final` | 67499–81000，路线 `final` |
| `--clear` | 78299–83900，路线 `clear` | 78299–83900，路线 `clear` |

在 PowerShell 中可按下例采样。根据上表替换环境变量和游戏。

```powershell
$mame = 'E:/Downloads/shmupmame_5.4_win64'
$script = (Resolve-Path tools/pgm/capture.lua).Path
$env:PGM_GAME = 'ddpdoj'
$env:PGM_MODE = 'primary'
$env:PGM_BOSS_ROUTE = 'left'
$env:PGM_FIRST = '7700'
```

## 已知差异

- 发弹归属和自机狙仍有未识别项。逐帧弹幕与部件轨迹来自有限的参考输入，LuaSTG 阶段跳转后可能接到不同的原动作相位。
- 旧版入口只覆盖已采到的关底状态，未击破的采样段用循环延长。两作均在一周目第五面击破后结算。部分普通敌机的受击、击破、分支和资源系统尚有缺项。
- TH44、TH45 此前的录像与第五面更新后的数据不兼容。
