# 停弹、等待与恢复运动的ECL修正

2026-11-03按原始ECL和复原源码核对并修改；本次按用户要求未启动游戏或运行测试。下表的时序是源码推导，不能视作实机采集结果。

## 438 神技「八方龍殺陣」

原始文件：`../workspace/original/ECL/th08/ecldata4a.ecl`；带地址反汇编：`../workspace/decompiled/ecl/8/ecldata4a.decl`。整数运算定义见 `../workspace/reconstructions/th08/src/EclManager.hpp`、`EclRunLow.inl`：**op10为整数加赋值，op11才是整数减赋值**。

白色小弹来自 `Sub37`。每次调用在同帧发15组、每组4颗；记录1的等待初值50，循环尾 `0x6b2c: ins_10(li0,3)` 递增3。当前移植误写成减3，导致越外侧的一组越早换色／启动，和原作相反。

| 组索引k，从0起 | 原实现WAIT | 原作／修复后WAIT |
| --- | --- | --- |
| 0 | 50 | 50 |
| 1 | 47 | 53 |
| 7 | 29 | 71 |
| 14 | 8 | 92 |

变换程序保留原始顺序：`REL(50,末速0) → WAIT(50+3k) → SPRITE(6,2) → WAIT(60) → SOUND → REL(1,末速1.8-0.053333335k)`。

从第一次运行FIRED更新记作第0帧，按 `BulletManager::OnUpdate` 的“先Advance、后更新活动变换”顺序推导：

| 事件 | 修复后时刻 |
| --- | --- |
| 减速完成，速度归零 | 50 |
| 换色并认领第二段WAIT | 102+3k |
| 以记录末速重新运动 | 164+3k |

最后一组原先在122恢复，修复后为206，纠正了84帧的差值。出生动画与新对象入帧口径不计入该表，也没有把WAIT值简单当成弹龄。

同卡 `Sub36` 的持续环弹也修正一处指令顺序：原作先CALL Sub35发弹，再累加／归一化枪口角（`0x6630→0x6640`、`0x6700→0x6710`、`0x67d0→0x67e0`）。移植原先先转角再发，导致阶段交界的首发角提前一步。近距离射击闸门跳过发弹时，仍照常更新枪口。

## 415 超人「飛翔役小角」

原作 `ecl16_d.ecl/Sub4`：`0x744` 写WAIT60，`0x76c` 写VEC60、加速度0.016666668；初速0.02。

原移植在WAIT倒数归零的下一帧立即加速，少了清活动位的一帧；加速速度还从0开始重算。修复为等待60次更新、随后清WAIT位、再于下一次更新认领VEC；加速度累加到初速0.02上。

参考：`../workspace/reconstructions/th095/src/BulletManager.cpp` 的 `AdvanceTransformProgram`、WAIT分支和 `UpdateVectorAcceleration`。只修正这条真实回调，没有更改出生过渡时长。

## 3600「風神様の神徳」

原作 `stage06.ecl/BossCard5_atN`、`BossCard5_at2` 为WAIT后接POLAR。专用手写枪原先倒数归零后立即加速，同样少一帧清WAIT活动位。

修复增加独立的WAIT活动状态。计数非正时清位，本帧保持原速；下一帧再加速。它也覆盖零／负WAIT的边界，而不是只把等待常量统一加1。

参考：`../workspace/reconstructions/th10/src/BulletRuntime.cpp` 的Advance→WAIT顺序。首发初速0.001、WAIT160、8次出生更新的情况下，第一次加速由弹体第168次更新改为第169次，与之前审计A02记录的原作顺序对应。
