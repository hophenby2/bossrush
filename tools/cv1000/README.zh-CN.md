# CV1000 关卡练习与离线采样

| 练习入口 | 原作版本 | 主流程 |
|---|---|---|
| TH46 | 《虫姬二人》1.5 Original | 第一至五面 |
| TH47 | 《Espgaluda II》Ageha | 第一至六面 |
| TH48 | 《虫姬二人》Black Label 日版 Original | 第一至五面 |

自机、敌机、敌弹和自弹都使用 LuaSTG 对象。每一面的背景按 EP1C12 绘制指令加载和滚动图块，关底推进和击破由本局伤害触发。关卡练习从第一面连续进入最终结算。

TH46 第一面移植了 15 条 `0x11`、三条 `0x23` 和 47 条 `0x13` 飞虫指令及其 `0x0f` 类敌弹，以及两只 `0x41` / `0x40` 蜈蚣的身体、碰撞、两段 `0x13` 发弹、五段击破演出、碎片及地面掉落。两条 `0x30` 大型飞虫已接入移动指令、寻向三路发弹、双矩形共享血量、击破爆炸、四节点尾气和小 P 道具掉落。九条 `0x31` 已接入禁入判断、振动与轨迹历史、侧炮与中央炮交替、双矩形共享血量、两节点尾气和击破掉落。三条 `0x32` 已接入两组移动程序、十八组振动及 108 点轨迹、两路炮、共享血量、两节点尾气、二十份击破爆炸和四份碎片。四条地面敌机已接入原版移动、滚动层位移、附肢历史、交替炮、1536 HP 受弹判定、六份碎片、十一份爆炸、残骸和五枚地面大金块。`0x34` 植物控制器、动态生成的 `0x33` 草和八条 `0x35` 大草丛指令已接入原生对象、判定、击破碎草及金块掉落。已有十二条飞虫指令读取蜈蚣禁入，另有九条读取中 Boss 禁入。`0x80` 中 Boss 已接入本体、三块共享血量的判定、两个退场分支、四组发弹回调、四处零件爆炸、破损部位喷烟、击破减速及粒子启动后的金块掉落。其余道中和关底的发弹与移动仍使用实战采样，其中发弹归属、瞄准、零件伤害与各档血量包含推定值。已移植金块、小 P 拾取与上述飞虫击破计分，其余掉落入口、原版计分规则和角色特技待移植。两版 Futari 的其它难度、隐藏战、Black Label 国际版，以及《大复活》仍未接入。《大复活》需要父集 `ddpdfk.zip`。

TH46 的普通蕾可通过原生 LuaSTG 自机运行定点移动与受击后的复活时序。SH-3 先在 `0x0c078f70` 积分，用 `0x0c285d10` 取方向，再在 `0x0c079f60` 更新射击状态与下一步速度。按住射击键 16 步进入低速射击。正常移动为每步 2.5 像素，低速为 1.25，斜向分量使用方向表的比例 `181/256`。画面坐标中的边界为横向 8–232、纵向 27–281。

第一面关底的 `boss1_core.lua` 已实现共享受弹核心，`boss1_guns.lua` / `boss1_guns_extra.lua` 已补上第一段五类炮台；`boss1_body.lua`、`boss1_pose.lua` 和 `boss1_motion.lua` 已补上出生字段、关节更新及移动槽；`boss1_draw.lua`、`boss1_view.lua` 已补上绘图与六个碰撞牵引点。`boss1_control.lua` 的入场及第一段三组主任务已通过 `boss1_bindings.lua` 连接真实炮台和 `boss1_tasks.lua` 演出任务，宽幅炮挂载原生 `0xa2` 火球，四种关底敌弹及落地回弹也已连接原生对象，**尚未挂入练习入口**。入口仍使用原有采样关底，录像版本没有提升。演出效果工厂、第二段攻击及其余弹型、转段演出、计分和最终爆零件仍需补齐，再一起替换；不能把组件对照当成原生关底通关。

`0x0c14b1b0` 的 Original 本体初始 HP 为 170752。`0x0c303ebc` 的六个矩形共用第 0 块零件的血量，绑定 `0x1f9c+i*0x8c` 的六组牵引点，点号顺序为 1、0、4、5、2、3。其左右 / 上下半径分别为 56 / 96、32 / 21、44 / 44、44 / 44、48 / 56、48 / 56。`0x0c14b690` 在第一段降到 66816 时立即把 HP 钳回 66816，设置第二段及换段无敌；过量伤害不带入下一段。第二段归零时撤掉六盒。击破抑制来自 `0x0c076890` 读取的全局管理器字段，当前核心通过显式输入接收该条件，没有用复活倒数代替。`0x0c14b9c0` 的两段超时均为 18000，倒数到负数才转段 / 击破；抑制击破时第二段超时重置为 300。伤害换段保留挡弹盒，超时换段先撤掉判定。

炮台从原回调移植为独立 `Class(object)`：`0x0c157c60 / 0x0c158070` 的头部连射、`0x0c157be0 / 0x0c157f80` 的五路扇、`0x0c157ce0 / 0x0c1581d0` 的左右侧炮。头部连射从每串两发起，每两串加一发，最多四发；串内每五步发射并最多转四格，串间等待 24 降至 20，速度偏移 0 加至 24。五路扇每发重新瞄准，按调用参数分别连射两发和四发。侧炮逐串换边，每两串增加一对偏移扇，保留每层八像素横向间距、36 格角差和 −4 速度偏移。小型侧炮指令与六串指令分别自然结束。炮台当前只向原生弹工厂接口提交发弹参数；新的 `0x31 / 0x34` 弹型、原始贴图及工厂展开尚未接入。

`check_futari15_boss1.lua` 对照 `0x0c14b690` 的 474 次真实命中，覆盖一次钳血换段和最终击破；十个原版炮台寿命共 1050 份计时状态，以及独立读取探针记录的 192 组发弹参数相符，其中十二组为五路扇。炮口读取本步本体位置、自机上一步位置与存活标志；第 11172 帧的自机受击发生在炮台瞄准之后，使用帧末存活状态会把方向错误改成 256。Windows Sub 隔离测试已通过真实低速束和自弹对共享矩形扣血、过量伤害钳血、无敌期自弹消耗、第二段刚好归零与七个判定对象的回收。三个炮台对象也通过实际引擎更新：六串侧炮提交 54 次发弹请求、两发五路扇提交两次请求，头炮收束当前连射，三者均自然回收并各通知一次结束。这些请求尚未生成新的弹型，仍须配合完整关底控制器完成战斗验证。

专用采样脚本不改血量、位置或禁发计数，`CV1000_KEEP_LIVES` 仅沿用补残机选项。它输出定长 `.actors`、真实命中的 `.hits`、炮台状态 `.guns`、独立出膛参数 `.shots` 和管理器状态 `.scene`。本次炮台样本从既有第 10600 帧状态续采到 12600；受弹样本从第 13000 帧状态续采到 15200。寄存器中的负发射坐标须先转有符号 32 位整数；侧炮越过左边时不能把它写成四十多亿。

本体初始化按 `0x0c14b1b0` 先清零，再以原字宽写入 `(120-camera,500)`、速度 16、72 组历史坐标、16 个非零振动初相、双侧标志及已移植血量字段。`boss1_body.lua` 以原生共享判定对象承载这些字段，换段通知同步段号和 HP；关闭时一并回收主任务管理器、移动、绘图对象及六盒。第 10892 帧构造器返回后的首条记录与初始化字段校验值相符，没有用战斗中途的姿态作为出生数据。

`0x0c14e450` 的 20 组振动及历史、双侧牵引状态由离线工具展开为固定 Lua 算式，游戏内没有 SH-3 解释器。`0x0c1561e0` 的高度积分保留每步 −6553 的加速度，落地返回事件供战斗控制器排入 `0x0c155da0`。用第 10896–15042 帧的 4012 对入口/返回核对了每次 1402 个字段，覆盖第一、二段、零件变化及两次落地。输入只补入两次调用之间原控制器修改的字段，期望值来自返回探针，不保存预计算姿态。压平分支时按后支配关系找汇合点；损坏标志必须按半字合并，错误读取长字会把另一侧标志带进来，造成断肢后的牵引点错位。

移动槽是独立 `Class(object)`，保留初始化入口下一步执行、先积分并更新关节再寻向 / 加减速的顺序。已移植 `0x0c14f630` 的直接积分、`0x0c14f7e0 / 0x0c14f6d0` 的 ±24 / ±12 寻点与每步四格转向、`0x0c14f870 / 0x0c14fa80` 的十六档加减速及半程切换、`0x0c14fa20 / 0x0c14f960` 的入场等待与额外位移。到达目标后先清速度，下一步再初始化速度 4 的寻点。默认随机输入仍接 LuaSTG 录像随机数，原版与粒子共用的随机队列未接入；回归中代入原版随机返回值，独立核对了调用次数及范围。

完整持续射击样本的 4039 次移动回调及另一份左右移动自机样本的 599 次回调，本体字段、私有计时、入口切换与随机调用均相符。后一份样本有 81 次非零相机位移，位移为 ±65536，相机范围 −65536 至 2621440。Windows Sub 隔离测试通过原生对象自动 `frame` 执行了这 4638 次回调，并核对全部状态和两次各八个对象的完整回收。测试中实际关卡仍按原入口运行，关底组件使用记录的外部控制输入，不能视为完整战斗主驱动已经接入。

`boss1_draw.lua` 离线展开 `0x0c14c260` 的整数绘图算式，保留负数截断、64 位乘积高低字、四态 / 五态关节分支、受伤叠加层、脚步事件和 34 个本体写回字段。曲线最多细分 30 次，来自关节更新 `0x0c14edbc` 的原始钳位；并非按某次实战删减。全部朝向的 6590 份原版裁片及锚点从绘图表导出，图集为 2048×4096。以第 11800 / 11900 帧两份独立工作 RAM 导出的 Lua 字节一致。

第 10600 帧续采的入场记录有 916 次绘图、242376 个精灵请求，其中 32 个逻辑帧执行了本体及受伤叠加两遍；第 11800 帧续采的战斗记录有 2199 次绘图、482145 个精灵请求。共 3115 次回调的全部 34 个写回字段、724521 份精灵的图号 / 定点坐标 / 深度 / 颜色 / 透明度 / 翻转，以及 89 次脚步事件均与独立探针相符。画面偏移输入范围为横向 −1123474 至 561737、纵向 −349525 至 524288，包含负数分支。期望值来自原回调返回及真实精灵申请，不把采样姿态用于运行时绘制。

`boss1_view.lua` 为独立 LuaSTG 对象，每逻辑步生成绘制清单，再从 `0x1f9c+i*0x8c` 同步六盒；`render` 只提交清单，不再次推进关节。原版绘制队列的独立提交探针确认深度 120 / 122 / 125 从小到大，同深度保持申请顺序；本体和叠加层统一依此排序。Windows Sub 实际对象自动更新通过了上述 3115 次绘图和全部精灵摘要、六盒坐标及两次各八个对象的完整回收。实际自弹碰撞各扣 256 HP；首次实测发现一颗弹在帧末回收前会重复命中重叠盒，已在首个回调先撤自弹碰撞，复测不再多扣。颜色两倍增益、亮部截断及加法混色目前使用 LuaSTG 近似代理；脚步音效、足印和抖屏仍等待主控制器接收事件，未把这些事件冒充已完成演出。

设 `CV1000_DRAW=1` 时保存 `.draw` 的入口 / 返回、`.draw-ops` 的独立精灵与属性 / 脚步请求，以及 `.draw-order` 的实际提交次序，同样要求 `-nodrc`。`check_futari15_boss1_draw.lua` 默认核对入场和战斗两组样本，还检查所有已请求裁片存在于图集中；可用 `FUTARI15_DRAW_FIXTURE` 单独指定一组。

`boss1_control.lua` 把 `0x0c14fe20 / 0x0c14fbf0` 的入场和 Original 第一段 `0x0c151610 / 0x0c151880`、`0x0c1516e0 / 0x0c151ba0`、`0x0c151740 / 0x0c151d50` 三组主任务移为固定 Lua 状态机。入场保留子演出存活查询、移动槽切换和 128 倒数；攻击保留两轮五路扇、头炮收束、两种侧炮挂载、左右目标交替、起跳及落地等待，参数均取原程序。主任务提供具名挂载接口，返回原生子对象并查询真实存活；禁止把采样帧号用作运行时推进条件。运动接口区分 `0x0c078730` 的同入口保留和 `0x0c0786a0` 的强制替换。

原版 `0x0c0783f0` 的主任务区有五个槽，按下标扫描。新任务若占用当前槽之后的空槽，会在同一步执行；若占用之前的槽，则等下一步。原生实现用一个管理对象扫描五个独立的 LuaSTG 主任务对象，避免引擎按对象出生顺序改变交接时机；每槽及管理器另以逻辑步号防止重复更新。单个攻击结束只释放自己的槽，整个管理器关闭时才经 `api.close` 清理仍存活的子任务。

从第 10600 帧续采到 15300 帧，八个已移植入口共 2307 次回调、1062 次具名接口请求与原版相符，覆盖七份主任务实例、一轮完整攻击循环及第二轮至换段前的状态、八个本体字段、各状态有效的私有计时及句柄、随机返回和三次当步挂载。第 11093、11716、12536 帧各执行两个主任务。期望值来自入口 / 返回、实际子任务挂载、查询和场景标志写入的独立探针；接口返回用于回归输入，游戏模块不包含这些记录。`check_futari15_boss1_control.lua` 还核对同逻辑步不重复执行，以及关闭和清理接口的幂等性。

`boss1_bindings.lua` 的 974 次存活查询直接读取真实子对象的结束状态；不从记录中取得查询结果。`boss1_body.lua` 先创建协调对象，再按移动、五槽主任务、炮台、二十槽演出、绘图的顺序推进组件，各组件以本局逻辑步号挡住引擎稍后的重复遍历。侧炮完成时按 `0x0c158370 / 0x0c15837c` 各挂一个左右关节收回任务。原版三十炮台槽的复用顺序及全局分配/随机竞争仍待统一，目前炮台按出生次序更新。

Windows Sub 隔离测试通过原生对象自动 `frame` 执行全部 2307 次主任务回调、1062 次请求和 974 次真实存活查询，结束后 158 份主/子任务与火球、本体六盒和各管理器全部回收。480 发的参数请求及 79 次外部演出接口在该测试中只计数，没有生成新弹型和演出图形；移动及跳跃物理仍由记录的外部输入提供，不能当作整场战斗与本局移动已经联调完成。练习入口保持原状，未接顺序模式。

`boss1_tasks.lua` 实现入场、闪光叠加、摆动、中央及双侧关节伸缩、抬头、跳跃烟尘和落地回弹的 28 个入口。二十槽中的新对象占用后方空槽时当步执行，前方空槽则等下一步。原版 2429 次回调、50 份生命周期、352 次接口及本体写回与独立探针相符。跳跃烟尘每两步请求一批两份烟粒子和两份地面飞沫，再按原方向表写 `0x18e4`，两份寿命均为初始化加 72 次更新。`0x0c155da0 / 0x0c156f10` 落地先提交两脚各两组四份图形和地面飞沫，再执行 86 步回弹、43 批后续烟尘；读取 `0x0c0760b0 / 0x0c0760d0` 的实际画面偏移，不能拿固定零代替实战输入。移动槽的 `land / entry_pose` 事件已挂到对应任务；单独的定点起跳用例以真实姿态积分触发一次落地并自然回收，没有代入落地时刻。这里只移植任务与请求；粒子图形分配、音效、抖屏来源及其它画面效果仍需原生工厂。`check_futari15_boss1_tasks.lua` 单独验证每个对象，不把尚未移植的演出槽竞争算作通过。

## 采样工具

已在 ShmupMAME 5.4 跑通 `futari15` 和 `espgal2` 的 EP1C12 绘制命令及纹理提取。驱动 `src/mame/cave/cv1k.cpp` 定义 SH-3 工作 RAM 和 320×240 可视区，`src/mame/cave/ep1c12.cpp` 的 `gfx_exec` 定义绘制、上传和裁剪指令。采样从设备的命令副本中读取数据；查看工具可以从同次运行的显存裁出单张素材。

```powershell
$mame = 'E:/Downloads/shmupmame_5.4_win64'
$out = 'E:/fork/.cv1000-futari15'
New-Item -ItemType Directory -Path $out -Force | Out-Null
$env:CV1000_TRACE = "$out/cmd.bin"
$env:CV1000_FIRST = '5250'
$env:CV1000_LAST = '6600'
$env:CV1000_VRAM = '6500'
$script = (Resolve-Path tools/cv1000/capture.lua).Path
Push-Location $out
try {
    & "$mame/shmupmame_5.4.exe" futari15 -noreadconfig -rompath "$mame/roms" -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script $script -seconds_to_run 120
} finally {
    Pop-Location
}
python tools/cv1000/analyze.py "$out/cmd.bin" --frame 6500 --sprite 5 --output "$out/sample.png"
```

- `futari15` 第 6500 帧读取 666 条绘制命令，`espgal2` 同帧读取 751 条。单次显存快照为 128 MiB。分析工具输出单张精灵并保留源、目标坐标。
- `espgal2.zip` 本次使用 `E:/fork/shmupmame_5.4_win64/roms` 的副本。两个提供的 ROM 目录均缺少 `ddpdfk.zip`，其中的 `ddpdfkl2.zip` 仅含 `placeholder`。
- 采样同时保存自机坐标。Futari 的横坐标在 `0x0c38aaf4`，Espgaluda II 在 `0x0c37d72c`，后一个 32 位字段为纵坐标。设 `CV1000_SHIFT=1` 时会在 5500 帧起输入右移。复测两作每个游戏步进分别移动 2.5 与 2.75 像素。
- 可用 `CV1000_SNAPSHOT_ONLY=1` 只写显存样本。可用 `CV1000_RAM_FRAMES='6500,6501,6600,6601'` 保存少量完整工作 RAM，文件名附加 `.ram.<帧号>`。用 `CV1000_STATE` 指定本地 ShmupMAME 存档的绝对路径时，采样从该存档继续，帧号以采样进程启动为起点。只读使用现有存档。
- 长时间采样可用 `CV1000_KEEP_LIVES=1`。普通采样中，Futari 的 `0x0c38aabc` 和 Espgaluda II 的 `0x0c37d6fc` 在自机坠落时依次从 `0x01000003` 降到 `0x01000002` 和 `0x01000001`。该选项只补回这个计数，游戏仍按原逻辑处理受击、清弹和复活。
- 在两个游戏的连续样本里确认了各有一组 128 项定点位置记录。Futari 在 `0x0c517ed8` 记录第一个横坐标，步长 `0x54`。Espgaluda II 在 `0x0c4b5028`，步长 `0x2c`。位置后的两个 32 位字段是每次更新的位移。还需要区分会产生伤害的敌弹、预备弹和绘制特效，并确认敌机、发弹归属及关底状态。
- Futari 日版 Black Label 的自机横坐标在 `0x0c383a68`，残机计数在 `0x0c383a1c`，实测横移 3 像素/游戏步进。自弹对照用 `CV1000_FIRE` 指定按键起止帧。查看器用 EP1C12 第 29 位判定带透明绘制时哪些像素可见。
