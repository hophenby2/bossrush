# CV1000 关卡练习与离线采样

| 练习入口 | 原作版本 | 主流程 |
|---|---|---|
| TH46 | 《虫姬二人》1.5 Original | 第一至五面 |
| TH47 | 《Espgaluda II》Ageha | 第一至六面 |
| TH48 | 《虫姬二人》Black Label 日版 Original | 第一至五面 |

自机、敌机、敌弹和自弹都使用 LuaSTG 对象。每一面的背景按 EP1C12 绘制指令加载和滚动图块，关底推进和击破由本局伤害触发。关卡练习从第一面连续进入最终结算。

TH46 第一面移植了 15 条 `0x11`、三条 `0x23` 和 34 条 `0x13` 飞虫指令及其 `0x0f` 类敌弹，以及两只 `0x41` / `0x40` 蜈蚣的身体、碰撞和两段 `0x13` 发弹。十二条飞虫指令由蜈蚣的禁入状态决定。其余道中和关底的发弹与移动以实战采样重建。敌弹识别、发弹归属、瞄准、零件伤害与各档血量仍有推定值。各作还缺独立零件击破分支、原版计分和角色特技。两版 Futari 的其它难度、隐藏战、Black Label 国际版，以及《大复活》仍未接入。《大复活》需要父集 `ddpdfk.zip`。

TH46 的普通蕾可通过原生 LuaSTG 自机运行定点移动与受击后的复活时序。SH-3 先在 `0x0c078f70` 积分，用 `0x0c285d10` 取方向，再在 `0x0c079f60` 更新射击状态与下一步速度。按住射击键 16 步进入低速射击。正常移动为每步 2.5 像素，低速为 1.25，斜向分量使用方向表的比例 `181/256`。画面坐标中的边界为横向 8–232、纵向 27–281。

在 MAME 0.275 用 `-nodrc` 对照第 5486–5910 帧，位置、速度和低速射击状态 425 帧相符。另一次自然受击中，第 5556 帧失去一命，`0x0c0799b6` 的坠落至第 5605 帧结束，`0x0c079540` 在第 5636 帧重建自机并写入 255 步无敌。练习入口继续采用现有的初始位置、射击、炸弹和受击效果。运行 `luajit tools/cv1000/check_futari15.lua` 可检查轨迹中的关键帧。第二只蜈蚣影响实战碰撞和发弹，TH46 录像版本升为 9。目前只提供练习入口。

第一面的 `0x0c09bdaa` 读取 12 字节道中指令。`0x11` 类指令经 `0x0c0a1280` 筛选，由 `0x0c0a10c0` 初始化飞虫，由 `0x0c0a2940` 处理 16.16 位移、寻向和发弹。第 5485 至 7868 帧有 13 次成功挂载，第 5935 帧同时生成三只。第 7039 和 7055 帧读到的两条指令均未触发挂载。在保持原程序运行并锁定受击保护的一次采集中，核对了 13 只飞虫共 2203 条位置、朝向、发弹计时和振翅状态记录。

`0x23` 类指令的三只飞虫在第 5589、5609、5628 帧生成。`0x0c0a14c0` 初始化，`0x0c0a1670` 翻转横坐标，再由 `0x0c0a2cc0` 处理减速发弹、静止、调头和加速离场。用同样的受击保护设置核对了 585 条位置、速度、朝向、发弹计时和振翅状态记录。第 5589 帧生成的飞虫在第 5666 帧减到零速，保持待发计时 16，进入离场状态。

`0x13` 类指令经 `0x0c0a16c0` 进入同一个更新回调，保留正常横坐标。第 5839 至 7807 帧有 11 只通过两次采样都观察到的挂载，与 `0x23` 三只合计核对了 2717 条对象状态记录。末段原表卷轴位置 465–496 的 13 只在两个原版分支里都成功挂载，以未射击、无受击停顿的逻辑帧为准接入。末段另核对了 2448 条对象状态记录，覆盖位置、速度、朝向、发弹计时与退场。

原表从 `0x0c1ede00` 开始，`0x0c0a27c0` 检查 `0x0c41b4a8`、`0x0c41b4b0`、`0x0c41b4b4` 才决定是否挂载。中 Boss 的 `0x0c120b5a` 写入 `0x0c41b4a8=2`，`0x0c121762` 在超时分支清除它。第 378 个卷轴位置的 `0x13` 指令在未射击的第 8866 帧被跳过，在持续射击的第 8948 帧成功挂载。中 Boss 的禁入状态待接入。

第一只 `0x41` 蜈蚣在第 6175 帧挂载，初始 HP 3456。`0x0c0ace50` 更新卷轴位置与三组曲线控制点，`0x0c0ac610` 通过 `0x0c2dc9b0` 的表取六节贴图和各节锚点，最后一节设置 48 像素半宽、半高的矩形。第 6523 帧由 `0x0c0ad682` 开始禁入。未射击样本在第 7226 帧自然退场；持续射击样本在第 6624 帧 HP 降到 −15，至第 6747 帧退出禁入。同一批七条指令在前一分支全部跳过，后一分支挂载了后四只。练习入口按当前蜈蚣状态执行这些指令。差异 1，牵引点偏移和首次扇弹等待使用 LuaSTG 录像随机数。差异 2，阴影混色和击破闪光用 LuaSTG 颜色近似，原版爆炸与掉落待移植。

将原版牵引点随机偏移和受伤结果代入移植代码后，未射击样本 1050 步、持续射击样本 571 步的控制点、身体朝向及牵引点位移一致。Windows LuaSTG Sub 的练习入口也通过了自弹打中蜈蚣、解除禁入后挂载四只飞虫及退出关卡的检查。

`0x0c0ad9e0` 从第 6523 到 6586 帧每隔 9 步发三颗 `0x13` 敌弹。`0x0c0ac080` 在扫射结束后从四路起发扇弹，计时每轮重置为 64，发弹数每轮加一，路间角为 `16+2*发弹数`。未射击样本第 6628、6693、6758 帧各发四、五、六路。敌弹用 `0x093b` 起的朝向图及共用的出生闪光。按该图集在练习关第 1132–1201 帧剔除了 141 条旧采样记录。原版 `0x0c06e6f0` 在碰撞后解除敌弹判定，速度减半并换到 `0x0a9f` 起的消弹图，每两步换一格，共 32 步。

在 MAME 0.275 记录 `0x0c06e350` 分配的弹槽，将原版初次等待和牵引偏移代入后，39 发的生成时刻、发射点、朝向和速度，以及 2053 条在场位置和速度记录相符。在 Windows LuaSTG Sub 中，受保护的自机与蜈蚣敌弹碰撞时触发消弹，残机扣除次数不变。

第二只 `0x40` 对应卷轴位置 388。未射击样本在第 8946 帧挂载，持续射击样本在第 9028 帧挂载。练习关采用未射击时间轴的第 3516 步，中 Boss 段仍由采样推进。七节身体用 `0x0c2dcaa0`，牵引高度 130，卷轴按照两份记录中相同的像素步进从每步 1 像素降到每两步 1 像素。第二只的初段 `0x0c0ad7f0` 每波三发，两颗侧弹各偏 4 个角度单位。未射击样本第 9218、9283 帧发出四、五路扇弹，至第 9771 帧退出禁入；持续射击样本第 9349 帧 HP 降至 −67，第 9472 帧退出禁入。卷轴位置 440–443 的五只飞虫据此挂载。练习关第 3876–3924 帧中对应的 36 条蜈蚣旧弹轨已移除。

代入两份原版记录的击破时机和牵引随机数后，第二只蜈蚣未射击样本的 824 步、持续射击样本的 443 步位置与朝向相符。未射击样本的 33 发敌弹生成参数和 1823 条在场位置、速度记录相符。Windows LuaSTG Sub 的练习入口通过了两只蜈蚣的碰撞、击破、自然退场及飞虫挂载检查。

首只飞虫位于 `0x0c464760`。第 5521 帧经 `0x0c076960` 入发弹队列，`0x0c06e350` 分配敌弹，弹槽横坐标在 `0x0c3c64ec`。出生步速度为 64，`0x0c06e610` 给后续速度加入关卡基速 43、发弹参数 12 与 `floor(rank/32)`（单位均为 1/16 像素）。开场速度为 55。末段第 9991 帧的弹槽 `0x0c3e0ae0` 以速度 56 更新，定点速度分量为 `0x156c8` 与 `-0x33bc0`。两类飞行回调按 `36-floor(rank/16)` 初始化、`38-floor(rank/8)` 重置发弹计时。`0x0c06c290` 的计时项每 512 个逻辑步加 1，从第一面起点到第 10930 帧共 5501 个未射击样本与当前计时相符，击破等事件对 rank 的贡献待移植。第 5556 帧的扣命来自飞虫本体，碰撞盒半宽和半高为 18，敌弹为点判定。运行 `luajit tools/cv1000/check_futari15_road.lua` 可检查各批生成、首尾段发弹、碰撞及独立击破。

飞虫使用 `0x0c0a2580` 选择的 17 个朝向、每个朝向的四幅原版振翅图，以及 `0x0c2dafb4` 的绘制偏移。敌弹用 `0x0c285050` 的朝向折叠和 `0x0c06f0a0` 的四帧动画。生成当步绘制 `0x0a4b` 起的原版闪光，从下一步起绘制弹体和落后一格的残影。第 5524 帧的原版绘制命令记录了 `0x3aff` 混色。差异 1，残影使用 LuaSTG 加色近似 EP1C12 混色。差异 2，闪光相位的计数器按已移植的敌弹递增。投影与击破演出待移植。使用 `capture.lua` 的 `CV1000_RAM_FRAMES=5485` 和 `CV1000_VRAM=6500` 保存原版工作 RAM 和显存，即可重建图集。

```powershell
python tools/cv1000/export_futari15_road.py cmd.bin.ram.5485 cmd.bin.vram Resources/th46/stage1/road1.png
python tools/cv1000/export_futari15_road.py cmd.bin.ram.5485 cmd.bin.vram Resources/th46/stage1/worm1.png --worm
```

Futari 1.5 的 `CV1000_MOTION_TRACE` 输出 SH-3 位移槽写入的 TSV，列为帧号、PC、PR、总线地址、掩码和值。冷启动第 5485 到 5486 帧，`0x0c517ed8` 起、间隔 `0x54` 的 128 个记录中有 14 个位置变化，都能用对应速度解释。该池的 `0x0c0982a0` 分配函数由自机受击回调调用，例如 `0x0c079974` 发出的 11、12 类掉落物。首颗敌弹所在的池从 `0x0c3c64d8` 起，分配器使用 `0x0c3c458c` 的索引，槽的步长是 `0x94`。

## 导出整作

`campaign.py` 的 `LEVELS` 记录每面的起点、各场关底的区段和续采帧。冷启动轨迹使用 `CV1000_FIRST=5100`、`CV1000_FIRE=5450,95000`、`CV1000_KEEP_LIVES=1` 和 `CV1000_VISIBLE_ONLY=1`。三作依次在 72200、65300 和 65600 帧保存状态，从对应状态续采至末战结束，`CV1000_RESUME_FRAME` 和 `CV1000_FIRST` 分别填写保存帧及其后第二帧。重开模拟器时保持同样的按键与残机采样设置。

使用 `CV1000_EXTRA_VRAM` 记录道中和关底的显存。导出时用多个 `--vram` 传入 `cmd.bin.vram.<帧号>`，可用 `--stage` 重导其中一面。导出的数据包含每关的精灵和独立图集。

两版 Futari 第三面的地形素材会在同一显存地址滚动更新。冷启动后在 26500–43870 帧（1.5）或 24500–40850 帧（日版 Black Label）设置 `CV1000_UPLOADS` 为记录文件的绝对路径，可同时设 `CV1000_SNAPSHOT_ONLY=1`。将这次的文件交给 `campaign.py --stage 3 --uploads`，按原上传时序更新地形纹理。以第一面使用的资源生成器只提取通用自机图集和菜单预览。

```powershell
python tools/cv1000/campaign.py futari15 "$out/full/cmd.bin" "$out/end/cmd.bin" `
  --stage 2 --vram "$out/full/cmd.bin.vram.23000"
```

## 单面采样

使用 ShmupMAME 5.4 与 Python 3、NumPy、Pillow。以 `CV1000_KEEP_LIVES=1` 采集下表的范围，`CV1000_VRAM` 取主显存帧，`CV1000_EXTRA_VRAM` 取逗号分隔的额外帧。`CV1000_PREVIEW` 中指定任一实战帧生成菜单预览。每作在各自空目录运行，避免共用模拟器存档。

| ROM 集 | 连续采样 | 主显存帧 | 额外显存帧 |
|---|---:|---:|---:|
| `futari15` | 5100–18400 | 10300 | 7250、14000 |
| `espgal2` | 5100–18400 | 10300 | 6850、14000 |
| `futariblj` | 5050–17300 | 11200 | 7100、14000 |

`export.py` 可单独提取首面和自机资源。指定 `--output` 到采样目录可保留整作的首面数据。

## 采样工具

已在 ShmupMAME 5.4 跑通 `futari15` 和 `espgal2` 的 EP1C12 绘制命令及纹理提取。驱动 `src/mame/cave/cv1k.cpp` 定义 SH-3 工作 RAM 和 320×240 可视区，`src/mame/cave/ep1c12.cpp` 的 `gfx_exec` 定义绘制、上传和裁剪指令。采样从设备的命令副本中读取数据；查看工具可以从同次运行的显存裁出单张素材。

```powershell
$mame = 'E:/Downloads/shmupmame_5.4_win64'
$out = 'E:/fork/.cv1000-futari15'
New-Item -ItemType Directory -Path $out -Force | Out-Null
$env:CV1000_TRACE = "$out/cmd.bin"
$env:CV1000_FIRST = '5250'
$env:CV1000_LAST = '6600'
$env:CV1000_VRAM = '6500'
$script = (Resolve-Path tools/cv1000/capture.lua).Path
Push-Location $out
try {
    & "$mame/shmupmame_5.4.exe" futari15 -noreadconfig -rompath "$mame/roms" -video none -sound none -nothrottle -skip_gameinfo -autoboot_delay 0 -autoboot_script $script -seconds_to_run 120
} finally {
    Pop-Location
}
python tools/cv1000/analyze.py "$out/cmd.bin" --frame 6500 --sprite 5 --output "$out/sample.png"
```

- `futari15` 第 6500 帧读取 666 条绘制命令，`espgal2` 同帧读取 751 条。单次显存快照为 128 MiB。分析工具输出单张精灵并保留源、目标坐标。
- `espgal2.zip` 本次使用 `E:/fork/shmupmame_5.4_win64/roms` 的副本。两个提供的 ROM 目录均缺少 `ddpdfk.zip`，其中的 `ddpdfkl2.zip` 仅含 `placeholder`。
- 采样同时保存自机坐标。Futari 的横坐标在 `0x0c38aaf4`，Espgaluda II 在 `0x0c37d72c`，后一个 32 位字段为纵坐标。设 `CV1000_SHIFT=1` 时会在 5500 帧起输入右移。复测两作每个游戏步进分别移动 2.5 与 2.75 像素。
- 可用 `CV1000_SNAPSHOT_ONLY=1` 只写显存样本。可用 `CV1000_RAM_FRAMES='6500,6501,6600,6601'` 保存少量完整工作 RAM，文件名附加 `.ram.<帧号>`。用 `CV1000_STATE` 指定本地 ShmupMAME 存档的绝对路径时，采样从该存档继续，帧号以采样进程启动为起点。只读使用现有存档。
- 长时间采样可用 `CV1000_KEEP_LIVES=1`。普通采样中，Futari 的 `0x0c38aabc` 和 Espgaluda II 的 `0x0c37d6fc` 在自机坠落时依次从 `0x01000003` 降到 `0x01000002` 和 `0x01000001`。该选项只补回这个计数，游戏仍按原逻辑处理受击、清弹和复活。
- 在两个游戏的连续样本里确认了各有一组 128 项定点位置记录。Futari 在 `0x0c517ed8` 记录第一个横坐标，步长 `0x54`。Espgaluda II 在 `0x0c4b5028`，步长 `0x2c`。位置后的两个 32 位字段是每次更新的位移。还需要区分会产生伤害的敌弹、预备弹和绘制特效，并确认敌机、发弹归属及关底状态。
- Futari 日版 Black Label 的自机横坐标在 `0x0c383a68`，残机计数在 `0x0c383a1c`，实测横移 3 像素/游戏步进。自弹对照用 `CV1000_FIRE` 指定按键起止帧。查看器用 EP1C12 第 29 位判定带透明绘制时哪些像素可见。
